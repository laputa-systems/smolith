# Release

The workspace version is `0.3.0` in the root `Cargo.toml`. Upstream crate versions are only in `UPSTREAM.toml`.

A git tag names a source revision. No release tag is part of this tree, and nothing from this tree is published to crates.io yet.

`make publish` bumps the workspace to its next minor version. It commits and tags the release. It publishes the `laputa-*` crates in dependency order. Each release moves to `minor(max(local, registry)) + 1` with the patch reset. A registry that ran ahead becomes the base. The root `Cargo.toml` workspace version owns the release. The script updates that version plus the `laputa-*` versions in `[workspace.dependencies]`. It updates the `[components.*]` versions in `UPSTREAM.toml`. It updates the `laputa-smol` requirements in `tests/qualify` and `tests/consumer`. `tests/consumer` is its own workspace, so the release also runs `tests/consumer/check.sh` before committing: that resolves the new requirement and rewrites `tests/consumer/Cargo.lock`, which the release commit carries with the manifests so the `--locked` consumer and MSRV checks keep passing. One commit carries the release. Each crate gets a `<name>-v<version>` tag. The script checks for a Cargo registry login before any query or edit. It resumes a partial publication while HEAD stays on the matching release commit. Run it only when releasing. Set `TMPDIR` to the repository's `.work/tmp` for its backup files. Publish this workspace before an h12tiny release that drops its smolith path dependencies.

`tools/stage.sh` is the local publish check. It runs `cargo publish` for all 26 `laputa-*` crates against a localhost sparse index, without `--no-verify`. For that command only, crates.io is replaced by the staging index, which proxies every other crate. The workspace has no `[patch]` table. This nightly has no `cargo package --dry-run`. Publish verifies by packaging and building.

The script then checks each uploaded crate for `LICENSE-MIT`, `LICENSE-APACHE`, the absence of `[patch]`, and dependency names. A normal or build dependency must not use an upstream package name or a `tokio` name. Where the source manifest sets `default-features = false` on a normal or build dependency, the packaged manifest must keep that flag. Dev-dependencies are omitted from the published index. A fresh crate outside the workspace then builds `laputa-smol` `0.3.0` from the staging registry and runs its test. That consumer does not use a path dependency.

`tools/advisory-scan.sh` reads `upstream_name` and `upstream_version` from `UPSTREAM.toml`. RustSec has no entries under the `laputa-*` names, so a scan of those names alone is not evidence. The scan fails an unsound advisory when the pinned version is vulnerable and a normal or build edge reaches it under any feature set. An opt-in feature still counts as production. Dev-only hits are printed and do not fail the scan. The scan refreshes the advisory database and prints its revision and commit date. `--offline` reuses the checkout already present and says so. `laputa-event-listener` tracks event-listener 5.4.2, which is outside RUSTSEC-2026-0221.

`.github/workflows/ci.yml` pins third-party actions by commit. It runs Clippy, `cargo test --workspace`, `cargo check --workspace --all-features --all-targets`, the graph gate, the advisory scan, the consumer, the h12tiny fixture, the staging publish, a macOS test, and the musl checks from [platforms](platforms.md). Separate jobs run targeted Miri tests (local-task pinning, task metadata, a schedule callback that drops its runnable, detach across a scheduler panic and a begin-hook panic, executor shutdown), the Loom `close_during_force_push` model, isolated `--lib --no-default-features` checks for the crates that claim `no_std` or alloc-only support, and `cargo +1.85.0 check` for the workspace libraries and the external consumer. A workspace `--all-features` check unifies features and does not prove those minimal builds. The musl job compiles only. It installs `musl-tools` and points the musl C compiler at `musl-gcc`. The consumer and fixture scripts read TOML with the Python standard library, and `python3 -m unittest discover -s tests` runs the release-graph and staging unit tests as part of the verify job. The workflow does not run rustfmt.
